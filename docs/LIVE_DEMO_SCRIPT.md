# บทพูดและสคริปต์การสาธิตสด (Live University Demo Script)
### Mini Anti-Cheat: Process-Based Cheat Detection System
**วิชา:** Operating Systems and System Calls  
**ระยะเวลาที่แนะนำ:** 5 – 8 นาที  
**บทบาท:** ผู้นำเสนอ (1 คน หรือแบ่ง 2 คน: คนหนึ่งพูด/อธิบาย อีกคนหนึ่งพิมพ์คำสั่ง)

---

## 🖥️ การเตรียมหน้าจอก่อนเริ่ม (Pre-Demo Setup)

1. **ขนาดหน้าต่าง & ฟอนต์:** ขยายขนาดฟอนต์ของ Terminal ให้ใหญ่พอ (กด `Cmd +` หรือ `Ctrl +` ประมาณ 2-3 ครั้ง) เพื่อให้อาจารย์มองเห็นชัดเจนจากระยะไกล
2. **การจัดหน้าจอ:** แบ่งหน้าจอเป็น **2 ฝั่ง (Split Screen ซ้าย-ขวา)**:
   * **ฝั่งซ้าย (Terminal 1):** สำหรับฝั่งผู้ดูแลระบบ (Anti-Cheat Server / Monitor)
   * **ฝั่งขวา (Terminal 2):** สำหรับฝั่งผู้เล่น / ผู้จำลองการโกง (Hacker / Attacker)
3. **เตรียมไดเรกทอรี:** ทั้งสองหน้าต่างให้อยู่ที่ Root ของโปรเจกต์:
   ```bash
   cd ~/Coding/Project/Mini_Project/Mini-Anticheat
   ```
4. **เคลียร์หน้าจอ:** พิมพ์ `clear` ทั้งสองฝั่งให้สะอาดตา

```bash

```

🗣️ **[บทพูด]:**
> *"เริ่มมแรก เรามาตรวจสอบความสบูรณ์ของ Source Code กันก่อนครับ"*  
> *(รอ 1 วินาทีให้คอมไพล์เสร็จ แล้วชี้มือไปที่หน้าจอ)*  
> *"จะสังเกตเห็นว่า โค้ดทั้งหมดคอมไพล์ด้วยแฟล็กความปลอดภัยสูงสุด `-std=c11 -Wall -Wextra -Wpedantic -O2` โดยคอมไพล์ได้ไบนารีหลัก 3 ตัวคือ `anticheat`, `game`, และ `cheat_test` โดย**ไม่มี Compiler Warning หรือ Error แม้แต่บรรทัดเดียว**ครับ"*

> *"ผลลัพธ์คือ **PASS ครบทั้ง 18/18 Tests** ครับ"*

### [ฉากที่ 3] สาธิต Process Scanner และเปรียบเทียบกับคำสั่งของ OS
> **เป้าหมาย:** แสดงว่าเราอ่าน `/proc` Filesystem เองจริง ไม่ได้เรียกคำสั่งโกงอย่าง `system("ps")`

> **[การกระทำ - Terminal 1]:**
```bash
./anticheat | head -n 12
```

🗣️ **[บทพูด]:**
> *"ทีนี้เรามาดูการทำงานของโมดูลแรก **Process Scanner** ครับ"*  
> *(ชี้ที่ตารางผลลัพธ์)*  
> *"ระบบของเราใช้ `opendir()` เปิดอ่าน Virtual Filesystem ใต้ `/proc` โดยตรง และสกัดค่า PID, Parent PID, ชื่อ Process และ State ออกมาจากไฟล์ `/proc/[pid]/status`"*

> **[การกระทำ - Terminal 1]:**
```bash
ps -eo pid,ppid,comm,state | head -n 12
```

🗣️ **[บทพูด]:**
> *"เมื่อเราลองเทียบกับคำสั่งมาตรฐาน `ps` ของ Linux จะเห็นว่าค่า PID, PPID และ State ของโพรเซสตรงกันอย่างสมบูรณ์ และโปรแกรมของเรายังสามารถกรองโพรเซสเฉพาะกลุ่ม เช่น Zombie Process ผ่านตัวเลือก `--zombies` ได้ด้วยครับ"*

---

### [ฉากที่ 4] สาธิต Rule-Based Cheat Detection Engine
> **เป้าหมาย:** ชี้ให้อาจารย์เห็นนโยบายความปลอดภัย (Safety Policy) และการแยกแยะ Normal, Suspicious, Confirmed

> **[การกระทำ - Terminal 1]:**
```bash
./anticheat --detect | head -n 15
```

🗣️ **[บทพูด]:**
> *"ถัดมาคือ **Cheat Detection Engine** ครับ เมื่อเราสั่ง `--detect` ระบบจะประเมินทุกโพรเซสในระบบตาม Rule-Based Policy"*  
> *(ชี้แถวที่เป็น NORMAL)*  
> *"โพรเซสทั่วไปจะถูกจัดเป็น `NORMAL`"*  
> *"แต่ถ้าในระบบมีเครื่องมือจำพวก Debugger เช่น `gdb` หรือ `scanmem` ระบบจะจัดเป็น `SUSPICIOUS` พร้อมระบุเหตุผล แต่จะไม่สั่งแบนหรือสั่งปิดเด็ดขาด เพื่อป้องกันปัญหา False Positive กับโปรแกรมของนักพัฒนาครับ"*

---

### [ฉากที่ 5] ไฮไลต์ของการสาธิต: Live Interactive Game Protection (Split Screen)
> **เป้าหมาย:** แสดงการทำงานพร้อมกันของ `fork()`, `execvp()`, `pipe()`, `waitpid()`, `kill()`, และ Non-blocking IPC

> **[การกระทำ - Terminal 1 (ฝั่งซ้าย)]:**
```bash
./anticheat --launch --protect --interval 500
```

🗣️ **[บทพูด - ชี้หน้าต่างซ้าย]:**
> *"และนี่คือช่วงสำคัญที่สุดของการสาธิตครับ ในหน้าต่างฝั่งซ้าย ผมสั่งให้ Anti-Cheat ทำการเปิดและควบคุมเกมจำลองด้วยคำสั่ง `--launch --protect`"*  
> *"สิ่งที่เกิดขึ้นเบื้องหลัง ณ วินาทีนี้คือ:"*  
> 1. *"Anti-Cheat เรียก `pipe()` สร้างท่อสื่อสาร IPC"*  
> 2. *"เรียก `fork()` แตก Child Process และใช้ `execvp()` โหลดไบนารี `./game` ขึ้นมาทำงาน"*  
> 3. *"ตัวเกมส่งค่า Ticks, Health และ Score แบบ Real-time ผ่านท่อ Pipe กลับมาแสดงผล"*  
> 4. *"และเราใช้ `fcntl()` ตั้งค่า Pipe ฝั่งอ่านเป็น `O_NONBLOCK` ทำให้ตัว Anti-Cheat ไม่ค้าง และยังคงวนลูปสแกน `/proc` ทุกๆ 500ms ได้อย่างต่อเนื่องครับ"*

> **[การกระทำ - Terminal 2 (ฝั่งขวา)]:**
*(พิมพ์คำสั่งเตรียมไว้ แต่อย่าเพิ่งเคาะ Enter ให้พูดก่อน)*

🗣️ **[บทพูด - ชี้หน้าต่างขวา]:**
> *"ตอนนี้ฝั่งขวา ผมจะจำลองเป็น Hacker ที่แอบเปิดโปรแกรมโกง `cheat_test` เข้าสู่ระบบ ขอให้อาจารย์สังเกตหน้าต่างฝั่งซ้ายดีๆ นะครับ..."*

> **[การกระทำ - Terminal 2]:** เคาะ **Enter** รันคำสั่งทันที!
```bash
./cheat_test --mode score_hack
```

> **[สิ่งที่เกิดขึ้นบนหน้าต่างซ้าย]:** หน้าต่างซ้ายจะขึ้นตัวหนังสือสีแดงแจ้งเตือน Alert ทันที และเกมจะปิดตัวลงอย่างสง่างาม

🗣️ **[บทพูด - ชี้หน้าต่างซ้ายอย่างมั่นใจ]:**
> *(ชี้ที่ตัวหนังสือสีแดง)*  
> *"ทันทีที่ `cheat_test` ปรากฏขึ้นในระบบ Anti-Cheat สแกนตรวจพบว่าเป็น `CONFIRMED_CHEAT` จึงส่ง Alert แจ้งเตือนสีแดงทันที"*  
> *(ชี้ที่บรรทัด Protection Action)*  
> *"และกลไก **Active Protection** ทำงานทันที โดย Anti-Cheat ส่งสัญญาณ `kill(game_pid, SIGTERM)` ไปยุติ Child Process ของเกมอย่างปลอดภัย"*  
> *"จากนั้นเรียก `waitpid()` ดักรับสถานะ ทำให้ตัวเกมปิดตัวลงอย่างเรียบร้อย ไม่เกิด Zombie Process ค้างในระบบ และสังเกตได้ว่า โพรเซสอื่นๆ ในเครื่องไม่ได้รับผลกระทบใดๆ เลยครับ"*

### [ฉากที่ 6] ตรวจสอบประวัติเหตุการณ์ผ่าน Audit Log (POSIX I/O)
> **เป้าหมาย:** แสดงว่าระบบมีการเก็บหลักฐานที่น่าเชื่อถือด้วย System Calls พื้นฐาน (`open`, `write`)

> **[การกระทำ - Terminal 1]:**
```bash
tail -n 8 logs/anticheat.log
```

🗣️ **[บทพูด]:**
> *"สุดท้ายนี้ เหตุการณ์สำคัญทุกขั้นตอนถูกบันทึกอย่างโปร่งใสผ่าน System Calls `open()` และ `write()` ลงในไฟล์ `logs/anticheat.log`"*  
> *(ชี้ที่หน้าจอ)*  
> *"เราสามารถตรวจสอบย้อนหลังได้ชัดเจนว่า: เกมเปิดตอนกี่โมง, พบการโกงจาก PID ไหน, ระบบตัดสินใจทำอะไร, และเกมสิ้นสุดการทำงานเมื่อไหร่ครับ"*

## 🛡️ แผนสำรองกรณีฉุกเฉินระหว่าง Demo (Troubleshooting & Fallback)

| สถานการณ์ | สาเหตุ | วิธีแก้ปัญหาเฉพาะหน้าอย่างมืออาชีพ |
|---|---|---|
| **พอร์ตหรือโพรเซสเกมเก่าค้าง** | รันเทสต์ค้างไว้ก่อนหน้า | รันคำสั่ง `killall -9 game cheat_test 2>/dev/null` แล้วเริ่มใหม่ |
